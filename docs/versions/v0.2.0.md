# v0.2.0 — the deepening pass

**Status:** planned · **Written:** 2026-08-28 · **Follows:** v0.1.0, the spine

v0.1.0 made the spine run. A message typed into the browser reaches the model through the skill
router, the mind and the turn orchestrator, and comes back as Server-Sent Events the interface
renders — with tools, permissions and her own stance along the way.

What it does not do is **accumulate**. Every conversation starts from nothing. She cannot produce a
thing you keep, only prose you copy out of a code fence. Projects are a database row with no way to
make one. And the two packages `ARCHITECTURE.md` names as v0.2 — `hera_memories` and
`hera_promptevo` — do not exist as directories. (`hera_promptevo` now belongs to
[v0.3.0](v0.3.0.md); see below.)

This version is the pass that fixes that, in the order the work unblocks itself:

**organise → produce → remember**

That order is not aesthetic. Projects are first because they are almost built already and
everything else gets filed under them; artifacts need a place for the bytes before memory can reuse
the panel beside them.

**It was five milestones, and two of them left before the tag.** Both are written down here rather
than deleted, because *we decided not to* is the thing that gets remembered as *we forgot*:

- **M5, dreaming and experience training → [v0.3.0](v0.3.0.md).** Not because it got harder. The
  milestones under it want to be stable before anything starts proposing changes to them, and this
  is the release Hera has to be usable daily for. It is also the only one that costs nothing to
  defer: every dependency arrow points *into* dreaming and none point out, so there is no
  half-built seam left behind.
- **M3, the redesign pass → [v0.2.1](v0.2.1.md).** The drawer was the part of it that anything
  depended on, and it was built early with artifacts because that is the panel that needed it. What
  is left — the rail hierarchy, the `⌘K` palette, the transcript rhythm — is polish, and polish is
  what a patch release is for. Shipping the capabilities first also means the redesign gets argued
  with against a build that has all of them in it, which is what [`frontend.md`](../frontend.md)
  asked for in the first place.

**The milestones keep their numbers.** M3 is a note pointing at v0.2.1 rather than a gap closed by
renumbering M4 — every commit message, `status.md` entry and changelog line already says *M4* for
memory, and a document that renumbers itself after the fact makes all of them wrong.

## What reading the repository changed

Three findings moved this plan away from what it looked like on paper.

**Projects are already built on the server.** `hera_chats.Project` carries `instructions`,
`pinned_skills` and `default_profile_id`; `hera_core.api.projects` is complete CRUD;
`hera_chats.turn` already binds `SLOT_PROJECT` and already merges project pins behind chat pins;
`Rail.svelte` already discloses a project's chats inline. The gap is entirely interface — **there is
no way to create or edit a project.** So M1 is a screen and two columns, not a feature.

**There is no dream ADR.** The design worth keeping is in [`prototype.md`](../prototype.md) — the
memory tiers and their separate caps, the dedup thresholds, the governance split between `write()`
and `propose()`, the dream log — and it is retired German prose, not a decision record. Part of this
version is writing those records, because the prototype is explicitly *wrong about everything
structural* and citing it as authority is how the old shape comes back.

**`hera_skillsets.render` tells the model a lie.** Every selected skill with files beside it arrives
with the sentence *"This skill has further files beside it in `<path>`. Read one if this skill tells
you to."* She has no tool that can read a file. This is the actual reason Anthropic's
reference-heavy skills do not work, and it is one small tool away from being true.

## The line on Anthropic's skills

Anthropic's published skills want two things Hera lacks: reading a skill's bundled reference files,
and running its bundled Python scripts. **v0.2 does the first and not the second.**

That splits them cleanly rather than half-supporting all of them. `brand-guidelines`,
`canvas-design`, `dataviz`, `frontend-design` and `web-artifacts-builder` are reference-heavy — they
read `references/*.md` and emit a document, which is exactly artifacts plus resource reading.
`pptx`, `docx` and `xlsx` shell out to Python, and will say so plainly instead of failing strangely.

**The sandbox was pulled into this version and then put back.** The reasoning is worth keeping,
because the mistake is one that is easy to make twice: it looked like a prerequisite for artifacts,
and it is not. `markdown`, `code`, `mermaid`, `html` and `svg` are *content* — an HTML artifact is a
sandboxed `iframe` in the browser, not a container on the host. The only thing running code is
load-bearing for is the script-running half of the skills above, which is a smaller prize than a
Docker dependency and a security claim to keep true.

What the excursion did produce is worth having:
[ADR 15](../adr/0015-running-code-in-a-container.md) answers the question
[`tooling.md`](../tooling.md) § 3 refused to let the sandbox start without — *a small sandbox for
testing, or safe?* — and that answer does not expire. It is the record v0.3 picks up from.

## The milestones

### M1 — Project folders — ✅ done

A project is a container with **behaviour**, not a folder — a name, its own instructions, its own
pinned skills, a default profile, and later its own files. [`frontend.md`](../frontend.md)
§ *Project or profile?* holds the line this depends on: a profile answers *who she is*, a project
answers *what we are working on*, and if a sentence would still be true in a project about something
else, it belongs in a mind region instead.

**Two columns.** `Project.default_agent_id` is the seam for agent selection — a bare `UUID`, unused
by the turn, rendered as a disabled control saying v0.3. That is the same precedent as Settings →
Dreaming: a feature you can see coming is a promise, one you cannot is a surprise.
`Project.color` gives the rail row an accent, so a project reads as a place rather than as a nested
list. Migration `0004`.

**`ChatPatch` grows `project_id`.** *Move this chat into that project* is the one organising verb
missing, and it is a field on an endpoint that already exists rather than a new one.

**A project screen**, at `/project/<id>` — not a Settings tab. Settings is *how she works*; a
project is the work. It carries the instructions editor, the pinned-skill picker (`SkillPicker`
already exists and already writes a list of names), the default profile, the disabled agent
selector, and the chats inside.

**The rail gains the affordances it is missing:** a **＋** on the `PROJECTS` heading and a `⋯` menu
per project. That is the chat row's mechanics with different items, and the existing
`menuFor`/`renaming`/`confirming` triple is reused rather than reinvented — three separate ids
because only one can be true at a time, and one mode field would let *renaming* survive the menu
closing.

**Project files are not in M1.** `frontend.md` is right that they need embeddings; they land in M4.
Until then the screen shows no files section rather than an empty one.

**What building it turned up**, both found by driving the real interface rather than by a test:

- **Enter commits twice.** Pressing Enter in the new-project field ran the handler, which unmounted
  the input, which fired `blur` on the way out — so the name was submitted a second time. Renaming
  had survived that by accident since v0.1, because the second call compares against the name it
  just set and does nothing. Creating did not: it made *two* projects, and the pair raced closely
  enough for the same slug that the loser came back a 500. Both commits are now guarded by the state
  field that was already there.
- **A disclosed project's `⋯` drifted into its chat list.** `.more` is absolutely positioned against
  the nearest positioned ancestor, and a project's `li` is as tall as the whole group inside it — so
  the button centred itself somewhere over a chat row, where it was both unreachable and blocking
  the row underneath. The project's own line now has its own positioning context.
- **Every selector became one component**, which was not planned for M1 and belonged here anyway.
  The project screen's controls were bare native `<select>`s next to a composer whose two pills were
  a native `<select>` with `appearance: none` — matching in the one place somebody had bothered, and
  even there dropping the platform's own list into an interface that draws everything else itself.
  `Select.svelte` is the composer's pill plus the skill picker's popup, used by both, and the rail's
  `⋯` menus were given the same frame. This is a down payment on M3 rather than scope creep: the
  drawer that milestone builds needs the popup vocabulary settled first.
- **Left standing, and pre-existing:** two projects created *concurrently* with the same name still
  race in `ProjectRepository._free_slug`, which checks and then inserts, and the loser is a 500
  rather than `hera-2`. Sequentially it is correct and has a test. Nothing in the interface triggers
  it any more, so this is a note rather than a fix — the honest repair is catching `IntegrityError`
  and retrying, and it belongs with whatever next needs `create` to be safe under concurrency.

### M2 — Produce: a scratchpad, artifacts, and somewhere to run code

The largest milestone, and the one [`tooling.md`](../tooling.md) § 5 calls *"the least specified"*.
It is two branches, and the split is a dependency rather than a preference: `tooling.md` § 5 says
*"nothing here should start before the scratchpad question is answered, because they want the same
storage and answering them separately produces two."* So **scratchpad → artifacts**, and the first
is useful standing alone.

A third stage, the sandbox, was planned here and has gone back to v0.3 — see *The line on
Anthropic's skills* above for why, and for what the excursion left behind.

#### M2a — The scratchpad, and a tool call that knows its chat — ✅ done

[ADR 12](../adr/0012-a-chat-has-a-scratchpad.md). `~/.hera/chats/<chat id>/scratch/`, three tools
behind one optional `Scratchpad` port, and `hera__note` keeps its own description and stops being
used for something it never described.

**The part that unblocks everything else is smaller than it sounds and easy to get wrong.** No
tool can currently know which chat it is in: her server is built once at startup, and
`ManagedServer` runs every call as a child of a worker task created at *connect* time — so a
`contextvars.ContextVar` set around the turn reads back empty, silently. The answer is MCP's
`_meta`: `ToolRegistry.dispatch` takes an opaque `context` mapping, `hera_mcp`'s tools take a
`ctx: Context` the SDK keeps out of the input schema, and the key travels through
`ChatsSettings.chat_meta_key` exactly as `hera__ask`'s name travels through `asking_tools`.

This is also what `hera__remember(scope="chat")` has been missing since v0.1, which is the sign
the seam is in the right place.

#### M2b — Artifacts — ✅ done · skill resources moved to [v0.2.1](v0.2.1.md)

[ADR 13](../adr/0013-an-artifact-is-a-file-she-publishes.md). ADR 14 was planned here and is now
one release later — see the note where it used to be described, below.

**An artifact is a file she publishes**, in a directory of its own beside the scratchpad:

```
~/.hera/chats/<chat id>/
  scratch/        her working notes. Hers, nobody reads them (ADR 12)
  artifacts/      what she publishes. Named, rendered, downloadable
```

Two directories rather than one with a flag, and the reason belongs to the *scratchpad*: it was
built to be somewhere she can think out loud unread, and a directory a person browses for the
deliverable is one she has a reason to be tidy in.

**Three tools.** `hera__artifact_create(name, content, inline)`,
`hera__artifact_edit(name, find, replace)`, `hera__artifact_read(name)`.

The middle one is the point. A tool that took the full content would be `create` under a second
name, and re-emitting a 40 KB page to change one colour is minutes of generation — which is what
has actually been failing against the target endpoint. `find` must match **exactly once**; zero and
several are both readable errors, because a replacement that hit the wrong one of three is a silent
corruption. `read` exists because `edit` is useless without it: in a later turn the content is not
in the conversation, only the card is.

**The filename is the identity and the extension is the kind.** No id, no title field, no `kind`
argument — the card's heading is the filename humanised by the same transformation `$lib/tools`
already applies to a tool name, and `.html` · `.svg` · `.mmd` · `.md` · code · anything else pick
the renderer. A model cannot disagree with its own filename.

**`inline` decides where it lands.** True draws it in the conversation where she made it — right
for a flow chart or a pie chart explaining the paragraph above it. False gives a card with an
**Open**, which is right for a page or a document. It is a boolean she is *told about* rather than
something she has to notice, which is what ADR 5 objects to.

**No index, no tables, no versions.** The directory is the store; the name, the flag and the kind
ride in the tool call and its result, which are already persisted events. So there is **no new
`ChatEvent` variant** — `ToolResultEvent.structured` already exists and is already `Any`. Content
is fetched by name rather than embedded, so a page never bloats the stored message, and one
consequence follows deliberately: an artifact has **one current state everywhere it appears**, so
editing it in turn nine changes what the card in turn four draws.

**The drawer moves here from M3.** It was planned as *one drawer, three panels*, built once before
there were three. This is the panel that needs it: the artifact full size, a download, and a file
bar listing every artifact in the chat. **It opens by itself** when she publishes something that is
not `inline`, because a page is a thing you look at and hunting for the **Open** on a card that is
still arriving is a step with nothing behind it; a figure she marked `inline` never opens it, since
it is already on screen where she drew it. Only while a turn is streaming — coming back to a
conversation leaves you where you left off. An `.html` one renders in a sandboxed `iframe` —
`allow-scripts` without `allow-same-origin`, so it has an opaque origin and cannot reach Hera's
storage. It *can* reach the network, which is written down rather than discovered: `sandbox` does
not stop a frame loading a font or an icon set, and a page without those looks broken in a way that
reads as Hera being broken.

**Skill resources moved to [v0.2.1](v0.2.1.md)**, and the description of the work goes with them.
It was always *a branch of its own on top of artifacts* — the two share nothing but the name guard
— so it is the one thing here that could be lifted out without leaving anything half-built.
[ADR 14](../adr/0014-skill-resources-are-readable.md) stands and is unchanged; what remains true and
uncomfortable is that `hera_skillsets.render` goes on telling the model a skill has files it can
read, and it still cannot. That is a lie in the prompt for one more release, and it is the reason
`read_resource` is first in v0.2.1 rather than last.

**What building the artifacts half turned up** — the rest is in [`status.md`](../status.md):

- **Mermaid is not in it.** `.mmd` renders as a code figure that says so. `mermaid` is a 2–3 MB
  browser dependency and a second sanitising path; an `.svg` covers a drawn chart today, and this
  is a lazy-imported component whenever somebody wants it.
- **A call's *arguments* are replayed under every later question**, which ADR 13 missed while
  keeping content out of the result for exactly that reason. A 40 KB page published in turn four
  was in the prompt of every turn after it, forever. `build_history` now shortens a string
  argument past `ChatsSettings.max_history_argument_chars` — a rule about size, because
  `hera_chats` may not learn which tools are hers.
- **`effect_update_depth_exceeded`, for the third time**, and a new shape of it: a store method
  that bumps a counter *reads* that counter, so calling it from an `$effect` makes the effect
  depend on what it writes. The symptom is the one that costs an afternoon — the page stops
  rendering mid-turn with nothing on screen to say why.
- **A drawing is a replaced element and a flex box will squash one.** An `<svg>` with `height:
  auto` is a flex item whose cross size is `auto`, so the default `align-items: stretch` took its
  height from the box: with a `max-height` above it, a 400 × 1400 flow chart was compressed to the
  panel's height and `preserveAspectRatio` then shrank the drawing to a thumbnail in an acre of
  white. It reads as an artifact that came out broken rather than as a layout that is wrong, which
  is the diagnosis ADR 13 does not want to hand to a person. The container is a plain block now and
  the scroll it already had is what handles a chart taller than the panel. There is an e2e test on
  the *proportions* rather than on the CSS, because nothing below a browser can see this.

**Twelve tools on her own server**, up from nine, and that is the honest cost of this milestone.

### M3 — The redesign pass — moved to [v0.2.1](v0.2.1.md)

**The one thing anything depended on was built early.** The drawer landed in M2b because artifacts
is the panel that needed it, and memory reuses that frame rather than bringing its own — which was
the whole load-bearing claim of this milestone. What is left is the rail hierarchy, the `⌘K`
palette, the transcript rhythm and the mobile sheet: real work, and none of it blocking anything.

Moving it is also the better order for the argument [`frontend.md`](../frontend.md) asks for. That
document says the design language gets adjusted once there is something to argue with; there is
more to argue with after four capabilities have shipped than after three, and an interface pass run
before the last of them would have been re-run afterwards anyway.

The two traps recorded in [`status.md`](../status.md) travel with the work:
`effect_update_depth_exceeded` stops Svelte rendering the page at all with nothing on screen to say
why, and by the end of this version there were **three** shapes of it rather than two.

### M4 — Memories — ✅ done

The half of `ARCHITECTURE.md`'s table that has been a promise since the rebuild started, and now the
last milestone of this version rather than the second-to-last.

**The shape changed before the work started, and the direction is a person's rather than a
schema's**: *a memory is a markdown file, and all of them are in the prompt.* It is settled in
[ADR 16](../adr/0016-a-memory-is-a-file-and-all-of-them-are-in-the-prompt.md), which supersedes
what this section said a week ago and keeps that design at the bottom rather than deleting it.

**Exportable, because a memory is the one thing here a person may want to take somewhere else.**
Everything else Hera stores is Hera-shaped — a chat, an event list, a permission rule. What she
knows about you is not: it is the part with value outside this application, and a row in a SQLite
table is the shape that makes it hardest to get out. So the store is files on disk, and markdown
rather than JSON, because markdown is the format that goes straight into a prompt and straight into
somebody else's tool with no conversion in between. **`MEMORY.md`** is the name, and it is the same
argument ADR 13 made for artifacts one milestone earlier: **the filename is the key.** A memory is
identified by what it is called.

**Injected whole, not retrieved.** Every enabled memory goes into the system prompt. This is the
reversal, and it is worth being explicit that it *is* one — the plan on this page a week ago was
cosine ranking with per-tier caps, and it is kept below rather than deleted, because if the budget
turns out to be the binding constraint, ranking is what comes back. The case for injecting
everything: retrieval that silently misses is the failure mode that matters. A memory that did not
arrive looks exactly like a memory that was never stored, and neither the person nor the model can
tell which happened. Everything present is a property you can check by reading the prompt.

**So the budget is the feature, not a setting.** Injecting everything means the space it takes is
unbounded by anything except what she has learned, and a prompt that grows forever ends as a turn
that fails at an endpoint's context limit — which is how this arrives as a bug rather than as a
warning. A ceiling in tokens, and it is a **visible** one:

- **A space-left bar on Settings → Memory.** Not a number in a corner. The one thing a person needs
  to know is *how close am I*, and a bar answers that before it is read. The same measurement is
  what stops the next memory being written when the ceiling is hit, so the bar and the refusal
  cannot disagree — one number, drawn once.
- **Deactivating keeps a memory and stops using it.** The middle option between keeping something
  and deleting it, and the reason it exists is exactly the budget: a memory that is true and rarely
  relevant should cost nothing and still be there. `enabled` was already in the field list for a
  different reason; this makes it the control a person actually reaches for. Disabled memories are
  still exported, still listed, still greyed rather than hidden.

**What this deliberately drops** — recorded because each was in the plan with an argument behind it:
per-tier caps, cosine ranking, the age hint on injected lines, and `hits`/`negative_signals`
tracking. If everything is in the prompt, there is nothing to rank and no tier to cap. **Write-dedup
survives** and is now the *only* thing that needs comparing text to text: the model will offer the
same fact twice and should not be punished for it, and with no retrieval to hide it, a duplicate is
now something a person sees. Normalised equality is cheap and catches most of it; whether the
embedder is worth keeping for the rest is an ADR 16 question.

**One file per memory**, `~/.hera/memories/<key>.md`, one fact each, front matter for
`scope · source · enabled` and prose under it. *A memory is a markdown file* and *the filename is
the key* only both hold if a memory **is** a file — one `MEMORY.md` per scope would make the
filename key the scope instead, and then an individual memory has no identity to switch off, to
diff, or for a tool to name. This is ADR 13's precedent one milestone later and the arrangement
`mind/` has used since v0.1. `MEMORY.md` is what an **export** produces: the enabled ones
concatenated, which is also very nearly what the prompt gets, so the thing you hand to another tool
and the thing she reads are the same text.

**At the ceiling she is asked to merge two.** The most ambitious of the three answers and the one
with the best outcome: two overlapping memories become one, the budget frees, and nothing is lost.
It is also the one with the most to go wrong, so the failure paths are part of the decision rather
than discovered later — **a merge that she declines, that comes back empty, or that would not free
enough space falls back to a refusal that names the budget**, and never to dropping something. The
rule underneath both: *nothing a person told her is discarded without a person present.* And it
happens mid-turn while somebody is waiting, so it is one round trip against the memories alone, not
a conversation.

**The rest, unchanged by either.** `hera_memories` is a package that declares its own
`Embedder` port rather than importing `hera_providers`, if it needs one at all. `hera__remember`
stops answering *"not available in this deployment"*. `SLOT_MEMORIES` gets bound. Memories carry
`auto`/`manual`, so a panel can say which she wrote and which you did. And whatever is on disk is
what is in the prompt — no cache in front of it that can be stale, because *the file is the truth*
is the property that makes the whole thing inspectable.

**What building it turned up** — the rest is in [`status.md`](../status.md):

- **A mind region had been telling her the opposite for a version.** `memory_instr` shipped with
  *"What you were given from memory is what you happened to recall, not the whole of what you
  know — never conclude that you cannot remember something."* That was honest about a design that
  ranked and capped, and it is false under this one. Left in, it would have her hedge about facts
  she is looking at. Found by reading the prompt rather than by a test, which is the point: prose
  and code can disagree for a long time without anything failing.
- **`hera_memories` needed *less* than the layering table had already given it.** Its allow-list
  said `hera_storage`, written when it was going to own a table. It owns a directory, so the entry
  is now `hera_home` — the one package in `ARCHITECTURE.md` whose *Owns* column mentions no table
  at all.
- **The front-matter split is duplicated from `hera_skillsets` rather than shared**, which the
  layering rule requires and which is the right answer for a second reason: a skill's format is
  Claude Code's and may not drift, and this one is ours. Sharing them would tie a decision about
  Hera's memories to somebody else's release notes.
- **The budget is over everything enabled, not over what one turn carries.** A chat-scoped memory
  is charged to the same ceiling even though only its own conversation carries it, because a person
  cannot steer by a number that changes depending on which chat is open. It over-counts slightly,
  which is the direction a ceiling should err in.
- **A nearly-empty bar has to still look like a bar.** At 15 of 4000 the fill is 0.4 % wide, and on
  `--surface-raised` alone the track was invisible — so the whole control read as a stray brass mark
  rather than as *plenty of room*. One outline fixes it, and it is only findable by looking.
- **A brain is the wrong shape for 13 px, and had to be drawn wrong to look right.** The mark
  started as a knot in a handkerchief and became a brain, which is the plainer picture — a knot is
  a promise to remember *later*, and what this marks is already in her prompt. But a brain's
  defining feature is fine convolution, which is exactly what dies at the size the gutter draws it:
  the first two drafts rasterised into a coin with a line scored across it. The shipped one has
  *exaggerated* scallops that survive, and it was picked by rendering five candidates side by side
  at 13, 15, 26 and 64 px rather than by drawing one and hoping.
- **Renaming what a gutter row shows can break a test that never mentions it.** Changing
  `remember`'s subject from the text to the key put the memory's key into the transcript — and the
  settings suite was waiting on `text=runs-models-locally`, which then matched the conversation
  *behind* the open modal and returned before the panel had its list. The same shape hid a second
  one: the transcript has an **Edit** on every message, so a page-wide `get_by_role` reached
  through the modal and clicked something the modal's own panel intercepted. Every assertion on
  that screen is scoped through the panel now.

<details>
<summary>The retrieval design this replaced, kept because the budget may bring it back</summary>

One table, `mem_memories`: `kind · scope · text · chat_id · project_id · source · hits ·
negative_signals · enabled · embedding`. Cosine above a floor ranks first, then keyword overlap,
tiebroken on `hits` and then id; nothing matching at all falls back to newest-first. Each tier
filtered and capped through its **own** budget rather than one shared pool — the prototype collapsed
them once and a noisy tier immediately crowded out a deliberately small one. Injected lines carry an
age hint, so she can tell *this was true in July* from *this is true*.

**Keyword overlap would be the default, not the degradation.** ADR 5 settled that for skills and it
applies harder here: a memory that silently stops arriving because embeddings are down looks exactly
like a memory that was never stored. An embedder that raises is treated as absent, and a turn never
fails on embeddings.

**The landmine, which survives any design that embeds anything.** `SkillRouter.select()` is
synchronous and `hera_chats` runs it in a worker thread, so reaching the event loop from there means
threading a loop handle down — and getting it subtly wrong deadlocks a turn. That is why v0.1 left
the embedder unwired rather than half-wired. The answer is to compute the query embedding in the
**async** part of the turn, before the worker-thread hop, and pass it down.

</details>

Six, indexed in [`adr/README.md`](../adr/) as they land — `tests/test_docs.py` fails on an unindexed

## Not in v0.2.0

## Verification

Per milestone, not at the end. The fast loop is `-m "not e2e and not live"`; `live` needs a real
model endpoint and never runs in CI.

Three repository guards catch a structural mistake before anything else is worth running, and each
new package has to satisfy all three:

| Guard | What it demands of `hera_memories` |
|---|---|
| `tests/test_layering.py` | An explicit allow-list per package. `hera_mcp`'s stays **empty** — the new ports are ports precisely so it never imports any of these |
| `tests/test_workspace.py` | Member in `[tool.uv.workspace]`, entry in the root `[tool.uv.sources]`, in mypy's `files` and coverage's `source`, and no test module shadowing another |
| `tests/test_docs.py` | ADRs 12–16 indexed, numbered and given a status |

End to end, the check that actually proves each milestone:

- **M1** — create a project in the rail, write its instructions, move an existing chat into it, send a
  message, and confirm the instructions reached the prompt rather than merely being stored.
- **M2a** — over two turns of one chat, have her write a plan to the scratchpad and read it back in
  the next turn; confirm the file landed under that chat's id and not another's, that a second chat
  cannot see it, and that deleting the chat removes the directory.
- **M2b** — ask for a page against a real endpoint: the card renders with its name and an **Open**,
  the drawer shows the page in a frame and downloads it, and a reload shows exactly what was
  streamed. Then ask for one colour to change and confirm `artifact_edit` does it without
  re-emitting the file. Then ask for a flow chart in the middle of an explanation and confirm it is
  drawn *there* rather than filed away.
- **M4** — tell her something in one chat, start another, and see it recalled. Then open the file on
  disk and confirm it says what she stored, in a form you could paste into something that is not
  Hera. Then disable it and watch the same question come back unanswered, with the bar on
  Settings → Memory showing the space it gave back.

One branch per milestone. `main` is protected — pull request for everything, squash merge, linear
history — and [`status.md`](../status.md) § *Merging into `main`* records the two traps that have
already cost a blocked merge.
